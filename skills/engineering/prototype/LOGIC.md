# 逻辑原型

一个让用户手动驱动状态模型的小型交互式终端应用。当问题关于**业务逻辑、状态转换或数据形状**时使用——那种在纸面上看起来合理但只有推过真实情况后才感觉不对的东西。

## 什么时候这是对的形状

- "我不确定这个状态机是否处理了 X 然后 Y 的边缘情况。"
- "这个数据模型真的能让我表示那种情况吗……"
- "我想在写之前感受一下 API 应该长什么样。"
- 任何用户想要**按按钮看状态变化**的情况。

如果问题是"这应该长什么样"——错误的分支。使用 [UI.md](UI.md)。

## 流程

### 1. 说明问题

写代码前，写下你正在原型化什么状态模型和什么问题。一段话，写在原型的 README 或文件顶部注释里。回答错误问题的逻辑原型是纯浪费——让问题显式，这样以后可以检查，无论用户现在在看还是 AFK 后回来。

### 2. 选择语言

使用宿主项目使用的语言。如果项目没有明显的运行时（如文档仓库），问。

匹配项目现有的工具约定——不要仅为原型添加新的包管理器或运行时。

### 3. 将逻辑隔离在可移植模块中

把实际逻辑——正在回答问题的部分——放在一个小而纯的接口后面，这个接口以后可以提取出来并放入真实代码库。围绕它的 TUI 是一次性的；逻辑模块不应该。

正确的形状取决于问题：

- **一个纯 reducer** — `(state, action) => state`。当动作是离散事件且状态是单个值时好用。
- **一个状态机** — 显式状态和转换。当"哪些动作现在合法"是问题的一部分时好用。
- **一小组纯函数**作用于纯数据类型。当没有隐含的当前状态——只有转换时好用。
- **一个有清晰方法表面的类或模块**当逻辑真的拥有持续的内部状态时。

选择最适合问题的形状，*不是*最容易接到 TUI 的那个。保持纯净：无 I/O、无终端代码、无用于控制流的 `console.log`。TUI 导入它并调用；没有东西反向流动。

这是让原型超越自身生命周期的关键。问题回答后，验证过的 reducer / 机器 / 函数集可以提升到真实模块——TUI shell 被删除。

### 4. 构建暴露状态的最小 TUI

构建为**轻量 TUI**——每次 tick，清屏（`console.clear()` / `print("\033[2J\033[H")` / 等效）并重渲染整个帧。用户应该总是看到一个稳定的视图，不是不断增长的滚动历史。

每帧有两个部分，按顺序：

1. **当前状态**，pretty-printed 且 diff 友好（每行一个字段，或格式化 JSON）。用**粗体**表示字段名或节头，用**暗淡**表示不太重要的上下文（时间戳、ID、派生值）。原生 ANSI 转义码即可——`\x1b[1m` 粗体、`\x1b[2m` 暗淡、`\x1b[0m` 重置。不需要引入样式库，除非项目中已有。
2. **键盘快捷键**，列在底部：`[a] add user  [d] delete user  [t] tick clock  [q] quit`。粗体按键，暗淡描述，或反过来——只要读起来清晰。

行为：

1. **初始化状态** — 单个内存对象/结构。启动时渲染第一帧。
2. **读取一个按键（或一行）**，派发到修改状态的处理器。
3. **重渲染**整个帧——不追加，替换。
4. **循环直到退出。**

整个帧应该能在一屏内显示。

### 5. 一条命令运行

向项目现有的任务运行器添加脚本（`package.json` scripts、`Makefile`、`justfile`、`pyproject.toml`）。用户应该运行 `pnpm run <prototype-name>` 或等效——永远不需要记住路径。

如果宿主项目没有任务运行器，就把命令放在原型 README 顶部。

### 6. 交付

给用户运行命令。他们会自己驱动；有趣的时刻是他们说"等等，这不应该可能"或"我以为 X 会不一样"——那些是*想法*中的 bug，这正是重点。如果他们想加新动作，加。原型会演进。

### 7. 捕获答案

当原型完成工作，唯一值得保留的是问题的答案。如果用户在，问他们学到了什么。如果不在，在原型旁边留一个 `NOTES.md`，这样答案可以在原型删除前填上（或由你填，如果你观察了会话）。

## 反模式

- **不要加测试。** 需要测试的原型不再是原型。
- **不要接到真实数据库。** 使用内存存储，除非问题具体关于持久化。
- **不要泛化。** 不要"万一以后想支持 X"。原型回答一个问题。
- **不要把逻辑和 TUI 混在一起。** 如果 reducer / 状态机引用 `console.log`、提示或终端转义码，它不再可移植。保持 TUI 为纯模块上的薄壳。
- **不要把 TUI shell 发到生产。** Shell 优化为从终端手动驱动。后面的逻辑模块才是值得保留的部分。
